# Contributing to hecdssr

Thanks for contributing. This guide covers the dev environment, the daily
loop, and the conventions that keep the package buildable on every
supported platform.

The user-facing install steps live in [`README.md`](README.md). This file
is for developers who are about to change code in the repo.

## 1. Prerequisites

Install these once on your machine.

| Tool | Notes |
| --- | --- |
| **R ≥ 4.5** | `winget install --id RProject.R` on Windows, or [CRAN](https://cran.r-project.org/) installer. |
| **Rtools** matching your R version | Windows only. `winget install --id RProject.Rtools` installs the latest. R 4.5 and 4.6 both use Rtools 4.5. |
| **Git** | Any recent version. |
| **R packages** | Run the line below in an R session. |

```r
install.packages(c("devtools", "roxygen2", "testthat", "pkgload",
                   "Rcpp", "R6", "xts", "zoo", "data.table"))
```

If R was installed system-wide and `install.packages()` complains the
library isn't writable, set up a user library first:

```r
dir.create(Sys.getenv("R_LIBS_USER"), recursive = TRUE, showWarnings = FALSE)
.libPaths(Sys.getenv("R_LIBS_USER"))
```

## 2. Clone & first-time setup

```sh
git clone https://github.com/HydrologicEngineeringCenter/hec-dss-r.git
cd hec-dss-r

# Fetch the platform-specific HEC-DSS shared library into inst/libs/.
# The C header (inst/include/hecdss.h) is vendored in-tree.
Rscript tools/download_hecdss.R
```

After the download completes:

- `inst/libs/hecdss.dll` (or `libhecdss.so`) — the runtime shared library
- `inst/include/hecdss.h` — vendored at the same pinned tag

The pinned tag is `HECDSS_VERSION` near the top of
`tools/download_hecdss.R`.

## 3. Project layout

```
R/                  hand-written R source. .R files document with roxygen2.
src/                C++ Rcpp shim.
  native.cpp        one wrapper per hec_dss_* C entry point. No business logic.
  dss_ptr.h         DssPtr typedef (Rcpp::XPtr with custom finalizer).
  hecdssr_types.h   auto-included into RcppExports.cpp (see "Custom Rcpp types" below).
  RcppExports.cpp   GENERATED — never edit by hand.
  Makevars[.win]    compile/link flags. Adds -I inst/include and -L inst/libs.
inst/include/       vendored hecdss.h.
inst/libs/          fetched DLL/.so (gitignored).
tests/testthat/     unit tests.
tools/              dev-only scripts (excluded from the built package).
examples/           runnable usage examples + a sample DSS fixture.
man/                GENERATED — regenerated by roxygen2.
NAMESPACE           GENERATED — regenerated by roxygen2.
```

## 4. The daily dev loop

From the package root, in an R session:

```r
devtools::document()   # regenerate man/ + NAMESPACE from roxygen tags
devtools::load_all()   # compile src/ and load — fast iteration
devtools::test()       # run tests/testthat/
devtools::check()      # full R CMD check (run before opening a PR)
```

`devtools::load_all()` re-runs `Rcpp::compileAttributes()` automatically,
so any new `// [[Rcpp::export]]` in `src/native.cpp` gets reflected in
`R/RcppExports.R` and `src/RcppExports.cpp` without a manual step.

### A note about PATH on Windows

When developing, `inst/libs/hecdss.dll` must be findable by the OS at
load time. The package's `.onLoad` adds the installed `libs/` directory
to PATH, but `pkgload::load_all()` uses a temp directory, so prepend the
source `inst/libs/` to PATH yourself before launching R:

```powershell
$env:Path = "$PWD\inst\libs;" + $env:Path
```

The standalone `Rscript tools/download_hecdss.R` is unaffected — it
doesn't load the DLL.

## 5. How to make changes

### Adding or editing R code

1. Write the function in the appropriate file under `R/`. Add roxygen
   comments (`#'` lines) for any function you want exported.
2. Run `devtools::document()` to regenerate `man/` and `NAMESPACE`.
3. Add or update a test in `tests/testthat/test-<topic>.R`.
4. Run `devtools::test()`.

### Adding a new C wrapper

The shim layer is intentionally thin: one `native_*` function per
`hec_dss_*` C entry point. Higher-level logic stays in R.

1. In `src/native.cpp`, add the wrapper with `// [[Rcpp::export]]` above it.
2. If the wrapper takes or returns a custom Rcpp type (e.g. `DssPtr`),
   make sure that type is declared in a header that
   `src/hecdssr_types.h` `#include`s. See the "Custom Rcpp types"
   section below.
3. Run `Rcpp::compileAttributes()` (or just `devtools::load_all()`,
   which calls it). This regenerates `R/RcppExports.R` and
   `src/RcppExports.cpp`.
4. Use the new `native_*` function from R-side code. Don't expose it
   to end users directly — it's internal.

### Custom Rcpp types — the `hecdssr_types.h` convention

If a `// [[Rcpp::export]]` signature uses a type that isn't standard
Rcpp (`int`, `std::string`, `Rcpp::NumericVector`, etc.), the
auto-generated `src/RcppExports.cpp` won't know about it and will fail
to compile. Rcpp solves this with a convention: it auto-includes
`src/<package>_types.h` in `RcppExports.cpp` if that file exists.

In this package, `src/hecdssr_types.h` `#include`s `dss_ptr.h`, which
defines `DssPtr`. To add a new custom type:

1. Define it in a header under `src/` (e.g. `src/my_type.h`).
2. Add `#include "my_type.h"` to `src/hecdssr_types.h`.
3. Use the type freely in `[[Rcpp::export]]` signatures.

**Never** edit `src/RcppExports.cpp` by hand — it's regenerated and your
changes will disappear.

### Adding a test

Create or extend `tests/testthat/test-<topic>.R`. Use `expect_equal`,
`expect_error`, etc. Keep tests deterministic — no network, no real
DSS file outside `examples/examples-all-data-types.dss` (which is
treated read-only by tests).

For an integration test that exercises the C shim:

```r
test_that("regular time series round-trips through DSS", {
    src <- system.file("..", "examples", "examples-all-data-types.dss",
                       package = "hecdssr")
    skip_if_not(file.exists(src), "example DSS fixture not present")
    # ... open, read, write to a tempfile copy, verify ...
})
```

## 6. Code style

- **R:** four-space indent, snake_case function names, roxygen docs on every
  exported function. Use `%||%` (R ≥ 4.4) for null-coalescing defaults.
- **C++:** four-space indent, `lower_camel` for parameters, `snake_case`
  for free functions. The shim layer should never contain business
  logic — date math, path parsing, and xts assembly all live in R.
- **Comments:** prefer commenting *why*, not *what*. Don't restate the
  code. A comment explaining a workaround for a known C-API quirk or
  a non-obvious invariant is the kind that pays off.

## 7. Updating the pinned HEC-DSS version

The package is pinned to a specific HEC-DSS C-library tag. Both the
binary (downloaded into `inst/libs/`) and the C header (vendored at
`inst/include/hecdss.h`) must match. To bump:

1. Pick the new tag from the [HEC Maven Nexus](https://www.hec.usace.army.mil/nexus/repository/maven-public/mil/army/usace/hec/hecdss/).
2. Edit `HECDSS_VERSION` near the top of `tools/download_hecdss.R`.
3. Re-vendor the header from
   [`HydrologicEngineeringCenter/hec-dss`](https://github.com/HydrologicEngineeringCenter/hec-dss)
   at the matching tag:
   ```sh
   cp /path/to/hec-dss/heclib/hecdss/hecdss.h inst/include/hecdss.h
   ```
4. Re-run `Rscript tools/download_hecdss.R` to refresh the binary.
5. Run `devtools::check()`. If the C API added or changed parameters,
   `src/native.cpp` will fail to compile with a clear error pointing
   at the affected `hec_dss_*` call. Update the wrapper to match.
6. Note the bump in `NEWS.md`.

## 8. Submitting changes

1. Create a feature branch off `main`:
   `git checkout -b feature/short-description`
2. Make your changes, run `devtools::check()` until it's clean
   (0 errors, 0 warnings, 0 notes).
3. Update `NEWS.md` with a one-line entry under the unreleased
   section. Behavior changes and bug fixes both belong there.
4. Commit. Aim for small, focused commits with messages that explain
   the *why*.
5. Push and open a pull request against `main`.
6. The GitHub Actions workflow at `.github/workflows/R-CMD-check.yaml`
   runs `R CMD check` on Ubuntu and Windows. Wait for it to go green.

## 9. Cutting a release

Maintainer-only:

1. Bump `Version:` in `DESCRIPTION` (semver).
2. Promote the unreleased section in `NEWS.md` to a real version
   header.
3. Make sure `devtools::check()` is clean.
4. Tag and push:
   ```sh
   git tag -a vX.Y.Z -m "Release X.Y.Z"
   git push --tags
   ```
5. On GitHub: **Releases → Draft a new release**. Pick the tag,
   paste the relevant `NEWS.md` section as the body, attach the
   tarball from `devtools::build()` if you want a downloadable
   source bundle.

## Gotchas worth knowing

- **`devtools::check()` will fail** if you forget to run
  `devtools::document()` after editing roxygen tags — the generated
  `man/*.Rd` will be out of sync with the source.
- **Don't commit `src/*.o`, `src/*.dll`, or `src/RcppExports.o`.** They're
  in `.gitignore`. The build artifacts come and go with every compile.
- **Don't commit `inst/libs/hecdss.dll`** — it's gitignored. Each developer
  fetches their own platform's binary with `tools/download_hecdss.R`.
- **`inst/include/hecdss.h` IS committed.** It's vendored, not fetched.
  The whole point is that the build doesn't depend on the network.
- **macOS isn't supported yet** — HEC doesn't publish a macOS build of
  the native library.
